# Raw data snapshots

These are frozen, point-in-time copies of the external sources the pipeline pulls from, so the notebooks can be re-run without depending on those services staying online or unchanged.

- **`spacex_api_launches_raw.json`** — the exact JSON response returned by the SpaceX launches endpoint (fetched via a static mirror of `GET /v4/launches/past`, used in [`notebooks/01_data_collection_api.ipynb`](../../notebooks/01_data_collection_api.ipynb) as `static_json_url` -- a fallback source when the live API doesn't respond). 107 launch records, saved with `requests.get(url).json()`.
- **`falcon9_wikipedia_launches_raw.html`** — the raw HTML of the Wikipedia snapshot used in [`notebooks/02_data_collection_webscraping.ipynb`](../../notebooks/02_data_collection_webscraping.ipynb) (`List of Falcon 9 and Falcon Heavy launches`, revision `oldid=1027686922`, fetched 2021-06-09). Saved with `requests.get(url, headers=headers).text`.
- **`dataset_part_1_reference.csv`** — a fully-resolved reference table (90 Falcon 9 launches × 17 columns: booster version, payload mass, orbit, launch site, landing outcome, etc.), used as a *second-level* fallback in notebook 01. The SpaceX API's per-record enrichment endpoints (`/rockets/{id}`, `/launchpads/{id}`, `/payloads/{id}`, `/cores/{id}`) proved less reliable than the bulk `/launches/past` endpoint during development; if those calls fail, the notebook loads this already-resolved table instead of re-deriving it, so the pipeline still completes end to end.

Notebook 01 falls back to `spacex_api_launches_raw.json` automatically if the live `/launches/past` request is unreachable, and separately falls back to `dataset_part_1_reference.csv` if the per-record enrichment calls fail (both have had recurring outages — see the notes in that notebook). Notebook 02's live source (Wikipedia) has been reliable so far, so it still fetches live by default; the HTML snapshot here exists purely as a reproducibility backstop if that ever changes.
